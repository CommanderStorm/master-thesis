\section{Introduction}\label{sec:intro}

Web maps rendered from vector tiles divide their work across two timelines.
When a tile arrives, the client decodes it and binds the active style to every feature it holds.
On each rendered frame, the client re-evaluates the view-dependent parts of that style and issues draw calls to the GPU.
Network and decode cost limit the first timeline, and the graphics device limits the second.
MapLibre GL~JS and Mapbox GL~JS both follow this model, streaming tiled geometry into the browser and driving a WebGL or WebGPU pipeline from a declarative style document (\cref{fig:pipeline_overview}).
If both of these stay inside the shared frame-time budget, the map pans and zooms smoothly.
Once either exceeds it, the interaction stutters.

A tileset served to millions of sessions pays for every redundant byte many times over.
Oversized tiles lengthen transfer, layers that never draw waste frame time, and attributes no client reads inflate decode cost.
On phones the same waste surfaces as heat and battery drain, and over the intermittent links found on trains and aircraft it surfaces as visibly empty maps.

Map production keeps styling and tiling apart.
Cartographers tune a style for appearance against a tileset that was encoded for general use, and no stage inspects the two together.
That separation can be exploited.
Suppose a filter tests a feature property and constant folding against per-tile statistics collapses that filter into a form that no longer names the property.
An encoder aware of this could drop the property's column from every tile, a reduction that neither style rewriting nor blind data pruning reaches on its own.
Whether such couplings deliver gains beyond the sum of their parts is the question this paper sets out to answer.

The database community faced the same shape of problem decades ago and settled it with the query optimizer.
A declarative query names the columns and predicates it needs, and the optimizer pushes projections and predicates down to the storage layer so that only the data a query actually consumes is ever read \citep{selingerAccessPathSelection1979,piraheshExtensibleRuleBased1992,graefeQueryEvaluationTechniques1993}.
Modern engines go a step further and let the pruned workload steer the physical encoding of the data itself \citep{armbrustSparkSQLRelational2015,dingSageDBInstanceOptimizedData2022}.
A map style is likewise a declarative specification over a tabular feature set, and we investigate this style- and data-driven co-optimization automatically, in the manner of a compiler and a query optimizer, making the following contributions:

\begin{itemize}
    \item A \textbf{formalization of joint style and tile co-optimization} as a transformation $\mathcal{O}: \mathcal{S} \times \mathcal{T} \to \mathcal{S} \times \mathcal{T}$ held to visual equivalence and strict idempotency.
    Compiler optimization and columnar encoding each cover one half of this space, and we are aware of no prior treatment that couples both under a single soundness criterion.
    \item A \textbf{three-level optimizer} and its end-to-end \textbf{implementation} against the MapLibre style runtime and the \ac{MLT} tile pipeline.
    Expression-level peephole rewrites run to a fixpoint, structural passes rewrite a typed style model through dead layer elimination, metadata refinement, and layer merging, and a tile level closes the pipeline with \emph{style-driven tile shaving}, which removes unused properties, values, geometry types, and feature ids, followed by \emph{adaptive multi-strategy encoding} into the \ac{MLT} columnar format.
    On \num{12} styles the optimizer had never seen, the style passes alone shrink the style by a median of \qty{30.8}{\percent} with no visual change, and the encoder alone produces tiles \qty{12}{\percent} smaller than gzip-compressed \acp{MVT}.
    \item An \textbf{evaluation} over multiple style corpora and 18 interactive scenarios with a cumulative ablation.
    The full pipeline cuts median load time by \qty{71}{\percent} and raises the sustained frame rate to a median of \num{2.5}$\times$, with discarding tile content the style never reads accounting for most of the gain.
    \item The \textbf{style-level} and \textbf{data-level} passes compose \textbf{additively}. The per-scenario synergy that does occur is too weak to lift the total, so each can be adopted on its own.
\end{itemize}
